# KV260 PCAM 5C Camera Vivado Project

Vivado hardware design for connecting a PCAM 5C camera to the AMD Kria KV260.
The design routes MIPI CSI-2 video through AXI VDMA to PS DDR memory and
provides I2C and GPIO interfaces for camera control.

This repository tracks the block-design Tcl, pin constraints, and project
settings needed to recreate the Vivado project. Generated project files,
build output, and exported XSA files are excluded from Git.

## Prerequisites

- AMD Vivado 2026.1
- Python 3.6.3 or newer
- Git with submodule support
- KV260 board files installed with Vivado

The block-design Tcl was generated by Vivado 2026.1. Opening it with a
different Vivado release may upgrade IP or change generated output.

## Clone

Clone the repository together with its build-script submodule:

```powershell
git clone --recurse-submodules <repository-url> kv260_pcam_5c
cd kv260_pcam_5c
```

If the repository was cloned without `--recursive`, initialize the submodule
before continuing:

```powershell
git submodule update --init --recursive
```

## Recreate the Vivado project

To recreate the project through the Vivado GUI:

1. Launch Vivado 2026.1.
2. Select **Tools > Run Tcl Script...** from the Vivado menu.
3. Open `scripts/checkout.tcl` from this repository.
4. Wait for the project to be created and opened.

This creates the project at:

```text
proj/kv260_pcam_5c.xpr
```

The default project name follows the repository folder name. The path above
assumes the folder is named `kv260_pcam_5c`.

Checkout creates a new project and requires that the target project does not
already exist. To clean and recreate it from the command line, run the
following command from the repository root:

```powershell
python .\scripts\clean_build.py -v 2026.1 --clean --checkout
```

The `--clean` option deletes generated content under `proj/`. Save the design
and run check-in before cleaning if you have changes to keep. For a fresh
clone, `--checkout` can be used without `--clean`.

## Build the bitstream

To recreate the project and run synthesis, implementation, and bitstream
generation:

```powershell
python .\scripts\clean_build.py -v 2026.1 --clean --build
```

Run this command from the repository root after saving any design changes
through check-in. To build the project already open in Vivado, use
**Generate Bitstream** in the GUI.

The Python helper searches common AMD/Xilinx installation locations for the
requested Vivado version. Add `-f` to skip its confirmation prompts.

## Export the XSA

Build the design and export a fixed hardware platform containing the bitstream:

```powershell
python .\scripts\clean_build.py -v 2026.1 --clean --build --xsa
```

With the current design's `system_bd_wrapper` top module, the expected output
path is:

```text
hw_handoff/system_bd_wrapper.xsa
```

To export again from an already-built project without rebuilding it:

```powershell
python .\scripts\clean_build.py -v 2026.1 --xsa
```

The export requires a completed bitstream build. `post_build.tcl` is currently
a placeholder, so generating a bitstream alone does not automatically export
an XSA.

Project recreation has been checked. Bitstream generation and XSA export are
currently being verified; camera capture on hardware has not yet been
validated.

## Check in design changes

After modifying and saving the design in Vivado:

1. Select **Tools > Run Tcl Script...** from the Vivado menu.
2. Open `scripts/checkin.tcl` from this repository.
3. Wait for the Tcl Console to report that the project has been checked into
   version control.

Alternatively, run the script directly from the Vivado Tcl Console while the
repository root is the current directory:

```tcl
set argv ""
source [file normalize "./scripts/checkin.tcl"]
```

The script overwrites `src/bd/system_bd.tcl` with the current block design and
copies constraints into `src/constraints/` when the destination files do not
already exist. Existing constraint files and `project_info.tcl` are preserved;
update those source files explicitly when changing constraints or project
settings.

Here, check-in means exporting design files for version control. It does not
create a Git commit. Review the resulting files before committing them:

```powershell
git status --short
git diff -- src
```

Generated files under `proj/` are not checked in.

## Repository layout

```text
.
|-- hw_handoff/                 # Exported XSA files (generated)
|-- proj/                       # Recreated Vivado project (generated)
|-- scripts/                    # Vivado repository/build helpers (submodule)
|-- src/
|   |-- bd/system_bd.tcl        # Recreates the IP Integrator block design
|   `-- constraints/
|       `-- pcam_5c_pin.xdc     # Camera MIPI, I2C, and enable-pin constraints
|-- post_build.tcl              # Optional post-build hook
`-- project_info.tcl            # Device, board, and project properties
```

Make design changes in Vivado, save them, and run check-in to export the block
design before recreating the project. Keep constraint and project-setting
changes in the corresponding source files.

## Key source files

- [`src/bd/system_bd.tcl`](src/bd/system_bd.tcl): Zynq UltraScale+ processing
  system, MIPI CSI-2 receiver, AXI VDMA, camera control, clocks, resets,
  interrupts, and address assignments
- [`src/constraints/pcam_5c_pin.xdc`](src/constraints/pcam_5c_pin.xdc): camera
  MIPI, I2C, and enable-pin constraints
- [`project_info.tcl`](project_info.tcl): target device and KV260 board settings
- [`scripts/README.md`](scripts/README.md): complete documentation for the
  checkout, check-in, build, archive, and export helpers
